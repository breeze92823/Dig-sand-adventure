# Dig Sand Adventure

Three.js (vanilla) + Vite. Foundation ported from `C:\ThreeJS\Clean-leaves-for-loot\Clean-leaves-for-loot` (the reference repo): sand ground, procedural textures/materials, lighting, Bloxity SDK + avatar, loading screen. No digging gameplay yet; the hub island (plaza, shops, portal, training area, dig lane, cliffs) is built as static scenery.

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN and our loading overlay.
- All tunables live in `src/config.js` (colors, light, fog, camera, physics, rig/proportions, `ANIM`, `MATERIAL_PBR`).
- `src/textures.js`: canvas painters (`sandTile`, `rockTile`, `sandMacro`), tileable, cached, seeded. `src/world.js`: ground (colour + bump map + non-repeating macro overlay), rocks, gradient sky with sun glow (recentred on the camera each frame), hemisphere + shadow-casting sun (follow point snapped to shadow texels), fog.
- `src/hub.js`: the hub island, a copy of the Roblox reference (north + south views): stud plaza walled by grass-capped orange cliffs (chequered south wall), grey outline strips, Sell Loot / Digging Tools / Trails / Upgrades stalls on glowing pads, hovering yellow quest drill in a square orange barricade pen (countdown + progress sign, sand motes), swirl portal, navy Training Area against the east wall (sign centred on the wall, rebirth pads, Digging Tools / Upgrades stalls in front), pink Leaderboards platform against the west wall with Sell Loot / Trails stalls in front, two boards, stairs and the purple Worlds ring (west), pink rug with picnic tables (south), dig lane with coloured luck bands running north to the sea between stepped terraces, loot with pickup glows at the lane mouth, palms, clouds, open sea all round. Layout/palette in `HUB` (config). Floating sign labels toggle with `HUB.labels`.
- `src/colliders.js`: solid AABBs registered by hub.js; `floorAt` (step-up aware) + `pushOut` wall sliding.
- `src/player.js` player singleton + movement; `floorAt` is the single floor lookup (ground + collider boxes; sample dune/hole height here). `src/camera.js` chase cam. `src/input.js` WASD/arrows, Space, mouse look (pointer lock), wheel zoom, Esc = portal menu.
- `src/bloxity.js` is the only place that touches the SDK and must never throw (SDK may be blocked). `src/avatar/`: `character.js` (player.glb base rig + procedural fallback), `loader.js` (equipped skin/parts/hats from the CDN, SDK proportions), `cdn.js`, `rig.js` + `animator.js` (procedural idle/run/air/land).
- `src/loading.js` + `loading.css`: steps `scene` / `auth` / `avatar` (`markLoaded`). With the SDK present the portal's overlay is used and fed step text; otherwise our sand-themed overlay shows. Optional logo at `public/ui/logo.png`.
- `src/dig.js`: the dig lane sand is a heightfield (one mesh per luck band, 0.5 m vertices, `DIG` in config). Hold left mouse / E to dig the 2.5 m cell in front of the player; harder luck bands dig slower, dug sand darkens, `dig.passable(x, z)` is true once a cell is dug through (the same test that blocks the player). `floorAt` reads it through `colliders.addFloorSampler`, so the player drops into holes. Digging starts right at the lane mouth (z = -14); only the lane side edges stay undug; undug sand blocks the player until fully dug (`DIG.passDug`).
- Loot: `src/data/loot.js` = reference catalog (9 rarities, ~80 items with $ values, rarity colours, `LUCK_LOOT`). `src/spots.js`: 13 luck bands (`HUB.laneBands`/`HUB.luck`, x1..x60, equal length like the reference zones), each tiled into ~6 m piles whose centres are loot spots (x1 = fixed plan `X1_DROPS` spread evenly; higher bands drop with a rising chance, `LUCK_LOOT.fullAt`); hub.js puts a prop on each spot. `DIG.hardness` = exponential per band (x1 = 1 ... x60 = `DIG.lastHardness` 4.18T). `src/lootDrops.js`: every spot rolls its items at build time for its luck band, models sunk so only their tops show through the sand, and each rises when its cell is passable (`dig.passable`); (`zoneOf(z)`: more items + higher rarity further down, band 0 = Common/Uncommon only) that float as the item's real 3D model (`lootModels.jsx` via the JSX->three helper `r3f.js`, JSX factory set in `vite.config.js`) with halo + label; loot left in the lane is lost after `DIG.lootLostDelay` s back in the plaza; NOT auto-collected, press E near one (`interact.js` prompt, `inputState.interact` edge; keyboard digging pauses while a drop is in reach, the mouse still digs) to put it in `player.bag` (`bagSlots`). `src/sell.js`: E at the Sell Loot pad (`SELL` in config) opens the window; Sell per item kind or Sell All (lock icon skips a kind) pays face value into `player.money` (no multipliers, Index milestones give no bonus). `src/loot.js` = Index window (`player.found` Set of names).
- Pets: `src/data/pets.js` (`EGGS`: one Starter Egg, paid in $ from `player.money`, 5 weighted pets with `power`; `PETS_BY_ID`), `src/pets.js` (logic: `petMultiplier()` = 1 + equipped powers, equip/delete, `tryHatch`), `src/petsWindow.js` (HUD Pets window), `src/eggWindow.js` (E at the egg stand, Hatch x1/x3) + `src/hatchOverlay.js` / `hatch.css` (shake -> flash -> reveal cards, click skips), `src/petFollowers.js` (procedural chibi followers on an arc behind the player). Egg stand built in hub.js by the portal (`EGG_STAND`, `HATCH_MS`, `PET_FOLLOW` in config). `petMultiplier()` scales Training strength gains (so dig speed) and Sell payouts. Pets are saved through `net.js`.
- Training / levels (`src/train.js`, `TRAIN` + `DIG.strengthExp` in config): standing on a Training Area pad (hub.js `trainPads`: mult / cost / paid) every `TRAIN.interval` s adds strength (`perTick` x `strengthMult(rebirths)` x pad mult) and the same perTick x mult as xp; `player.xpNext = xpPerLevel x level`, level capped at `REBIRTH.maxLevel`, "LEVEL UP!" banner + "+N Strength" popup. Rebirth pads need that many rebirths; the upper blue pads cost 5-9 rebirths (no pad is paid now). Digging speed x= strength ^ `DIG.strengthExp`; Sell payouts x `cashMult(rebirths)`; rebirth resets strength/level/xp. No Index bonus.

- Held shovel + dig animation: `src/heldShovel.js` builds the detailed shovel (skinned from `data/shovels.js`) in the right hand (`ArmR2_leaf` on player.glb, end of the arm on the procedural rig) with a fist; while digging a two-bone IK (`solveArm`) puts both hands on the shaft. `src/avatar/digStroke.js` samples the looping stroke (raise/thrust/hit/scoop/throw, `ANIM.dig` in config); `animator.js` `applyDig` blends torso lean + knee bend and emits `dig.impact` / `dig.thrown` (main.js turns them into sand puffs). Stroke speed scales with strength.
- Digging Tools: `src/data/shovels.js` = the reference's 28 shovels (Wooden free start ... Jadefang $480M, each with `bonus` strength, `cost`, look: shaft/grip/blade/trim colours, blade `shape`, `gem`, `glow`) + 2 locked Celestial quest rewards (shown, not buyable). `heldShovel.js` `skinShovel` reshapes/recolours the model per shovel; `src/shovelIcons.js` renders each model to a PNG for the `shovels.js` shop rows (buy -> Equip -> the hand model swaps).

- Multiplayer / saving: `src/net.js` (Colyseus client to `../Dig-sand-adventure-backend`, room `world`; `VITE_SERVER_URL_DEV` / `_MAIN`, else the Bloxity SDK resolves the endpoint, else offline). Loads/saves the `SAVED` keys of `player` (money, strength, level/xp, rebirths, sand, bag, sellLocked, found, shovels/shovel, trails/trail, upgrades, pets, nextPetId, discovered, daily, boosts; Sets go over the wire as arrays) - `progress` hydrates, `noProgress` pushes local state as the first save, changed progress is saved every `NET.saveEvery` s and on unload/hide; guests (`guest-` ids) are never persisted. Relays pose / shovel / trail / equipped pets / Bloxity avatar. `src/remotePlayers.js` draws the other players (default character + their cosmetics, held shovel via `attachHeldShovel(avatar, () => id)`, dig stroke, name tag; pets/trails of others are relayed but not drawn). `leaderboard` rows feed the two hub boards (`hub.boards.update`): the "Loot Collection" board ranks money, the other Strength (`BOARD_STATS` in hub.js). Loading has a `net` step. Backend ids/caps (`SHOVEL_IDS`, `TRAIL_IDS`, `PET_IDS`, `UPGRADE_MAX`, `WORLD_BOUNDS`) are kept in step by hand with `src/data/*.js` / `config.js`.
- Shared loot: online, the lane loot is the server's (`Dig-sand-adventure-backend/src/loot.ts`, `LOOT` + `LANE` in its constants.ts; room state `loot`, ~1000 items keyed by id). Same drop rules as `spots.js` / `lootDrops.js` (kept in step by hand, catalog in `src/data/lootCatalog.ts`). `lootDrops.js` mirrors `net.loot` every 0.2 s (drops are plain data; meshes are built within `VIEW_DIST` and freed past it); digging a cell free sends `lootFreed` (starts the item's `LOOT.lifetime` s countdown for everyone, last `BLINK_SECS` s it blinks), E sends `claimLoot` and the first valid claim gets it (`lootClaim` reply, otherwise "Someone else got it first!"). A claimed/expired slot respawns a freshly rolled item after `LOOT.respawnBase + respawnPerZone x band` s. Holes stay local per player; the client's "lost after leaving" and dig-zone loot re-roll apply only offline (online, a zone reset just re-buries the shared items locally). Offline / disconnected falls back to local rolls.
- Daily Rewards: `src/daily.js` + `daily.css` (HUD Daily button; 7 rewards per week, one claim per server UTC day via `serverNow()`) and `src/boosts.js` (timed 'strength' / 'cash' multipliers on `player.boosts`, applied in dig.js, train.js, sell.js). State is `player.daily` { day, week, last } + `player.boosts`, saved through net.js; backend `sanitizeDaily` / `sanitizeBoosts` (`DAILY_DAYS`, `BOOST_*` in constants.ts). Eclipse shovel (`shovelBonus` = 2x best owned regular shovel) and the Golden Sand Trail are granted on claim.

- Mobile / landscape: `src/device.js` (`isTouch`, `isCompact`, `installViewport` -> `html.compact`, `--W/--H`), `src/touch.js` + `touch.css` (touch devices only: floating move stick on the left of the world, drag-to-look + pinch-zoom on the right, hold-to-DIG and JUMP buttons, menu/fullscreen buttons, the "Press E" prompt becomes a tappable button, "rotate your phone" overlay in portrait; `body.win-open` hides the action buttons while a window is open). `input.js` ignores touch pointers and exposes `setDigHeld`. Window panels are em-based and scale with `min(vw, vh)`; `html.compact` at the end of `hud.css` re-lays the HUD (menu in a row, stats under it, depth bar on the right). Touch devices render with no AA and dpr <= 1.5.
- New-player tutorial: `src/tutorial.js` (banner + SKIP, 3D arrow trail/beacon, bobbing UI arrow on the button to press; phones get touch wording and arrows on the DIG / interact buttons), `src/tutorialLogic.js` (pure step machine `nextStep`), `src/tutorial.css`, `TUTORIAL` + `DISABLE_TUTORIAL` (`VITE_DISABLE_TUTORIAL=true`) in config. 11 steps: lane -> dig a cell -> dig until loot rises -> collect -> Sell Loot pad -> sell -> training pad -> train `TUTORIAL.trainSecs` s -> Digging Tools -> buy a shovel -> dig again; steps fall back when the player wanders off (no money for the shovel: banner asks them to dig + sell). Step is `player.tutorialStep` (a `SAVED` key; `player.tutorialReady` gates it until `net.js` read the save). Backend (`TUTORIAL_DONE_STEP`, kept equal to `TUTORIAL.steps`): a save with no `tutorialStep` is a returning player and gets 11 (finished); new docs start at 0; saves use `$max` so the step never goes back. A finished/skipped tutorial is also remembered per id in localStorage (`dsa-tutorial-done:<id>`) for guests/offline. Needs `dig.cellsDug` (dig.js) and `lootDrops.nearestFree` (lootDrops.js).
